NORTHWIND ANALYTICS SYSTEM ARCHITECTURE GUIDE
Fictional sample document for demonstration only

1. Overview
The Northwind platform is composed of an edge gateway, a stateless application tier, an
asynchronous worker tier, a relational primary store and a vector index used for semantic
search over customer documentation.

2. Component Responsibilities
2.1 Edge Gateway
The gateway terminates TLS, enforces rate limits, attaches a request id and validates the
session token before forwarding traffic. It performs no business logic.

2.2 Application Tier
The application tier is stateless and horizontally scaled. It owns request validation,
authorization enforcement and orchestration of downstream calls. Instances are replaced,
never patched in place.

2.3 Worker Tier
Workers consume a durable queue for ingestion, document parsing, embedding generation and
report rendering. Jobs are idempotent and keyed so that retries cannot duplicate work.

2.4 Data Stores
PostgreSQL holds transactional data. The vector index holds document chunk embeddings with
their metadata. Object storage holds original uploaded files. No component reads another
component's database directly; access is through the owning service.

3. Document Ingestion Architecture
Uploads are validated at the gateway and stored in object storage. A worker parses the
file, cleans extraction artefacts, detects structure, splits the text into semantically
coherent chunks, generates embeddings in batches and writes chunks plus metadata to the
vector index and the lexical index. Ingestion is resumable at each stage.

4. Retrieval Architecture
Search combines dense vector retrieval with BM25 lexical retrieval. Candidates from both
retrievers are merged with reciprocal rank fusion, deduplicated, then reranked by a
cross-model scorer. Only the top ranked chunks are passed to the generator, subject to a
token budget. Every retrieved chunk keeps its document, page and section metadata so that
answers can be cited.

5. Scaling and Capacity
The application tier scales on request concurrency; the worker tier scales on queue depth.
The vector index is sharded by tenant. Capacity reviews are quarterly and consider p99
latency, queue lag and index size rather than average utilisation.

6. Failure Modes
6.1 Dependency Failure
Calls to downstream services use timeouts, bounded retries with jitter and circuit
breakers. A degraded vector index falls back to lexical-only retrieval, and the response
records that retrieval was degraded.

6.2 Partial Ingestion
If embedding generation fails, the parsed and chunked output is retained so that only the
embedding stage is retried.

7. Security Architecture
Authorization is enforced in the application tier on every request, never at the client.
Service-to-service calls are mutually authenticated. Secrets are delivered as environment
variables at deploy time. Audit events for access to Restricted data are written to the
append-only audit log.

8. Observability Architecture
Logs, metrics and traces share the request id. Ingestion and query pipelines publish
per-stage durations and counts so operators can see which stage is slow. Token consumption
of generated answers is recorded per query for cost attribution.

9. Future Direction
Planned work includes parent-child chunk retrieval, query rewriting, a knowledge-graph
index for entity questions, and an offline evaluation harness measuring faithfulness and
answer quality against a curated question set.
